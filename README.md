# Question Cubes

Цифровые объёмные кубики для устного урока: один Teacher и два независимых ученика. Без заданий, оценок и аккаунтов.

## Запуск

Нужен Node.js 24.x. Сторонние зависимости не требуются.

```sh
npm start
```

Откройте http://localhost:3000. Учитель нажимает **Create a room** и передаёт ученикам код либо ссылку **Copy invite link**. Ученики вводят имя и код (при переходе по ссылке код уже заполнен). Каждый нажимает на свои четыре кубика; учитель видит оба набора автоматически.

Перед созданием комнаты учитель выбирает **LEVEL 1** (по умолчанию) или **LEVEL 2**. Level 1 сохраняет исходный вспомогательный кубик `DO / DOES / DO / DOES`; в Level 2 он содержит `DO / DOES / DID / CAN / WILL`. Остальные три кубика одинаковы. Уровень хранится в комнате на сервере: оба ученика получают его автоматически, а верхняя отметка показывает `LEVEL 01 · ENGLISH` или `LEVEL 02 · ENGLISH`. NEW ROUND сохраняет выбранный уровень; для другого уровня учитель создаёт другую комнату.

Также доступен **LEVEL 3 — PRESENT FORMS**: вспомогательный кубик `DO / DOES / IS / ARE / HAVE / HAS` и 18 состояний глагола: `PLAY / PLAYING / PLAYED / HELP / HELPING / HELPED / READ / READING / READ / EAT / EATING / EATEN / GO / GOING / GONE / DO / DOING / DONE`. Оба состояния READ сохранены. Отметка комнаты: `LEVEL 03 · PRESENT FORMS`. Грамматическая правильность не проверяется; уровень выбирает только учитель перед созданием комнаты.

Для проверки на одном компьютере используйте три независимые вкладки, открыв начальную страницу вручную. Сессия хранится в sessionStorage каждой вкладки и восстанавливается при обновлении. Дублирование вкладки может скопировать её сессию: для другого участника нажмите Leave room и войдите заново. Клавиши Tab и Enter/Space также позволяют вращать кубики.

С других устройств в той же локальной сети откройте `http://IP-КОМПЬЮТЕРА:3000`; сервер слушает все интерфейсы. Если потребуется, разрешите Node.js входящие соединения в частной сети Windows. localhost на другом устройстве не указывает на компьютер учителя.

## Архитектура

- `server.js`: HTTP-сервер Node.js; создание комнаты, два места, отдельные секретные сессии, проверка входных данных, передача событий SSE.
- `public/app.js`: вход, экраны учителя/ученика, быстрые повороты CSS 3D, очередь обновлений и повторная отправка после сбоя сети.
- `public/styles.css`: адаптивный интерфейс для desktop/tablet, 3D-грани и короткая анимация 160 мс.
- `test/rooms.test.js`: проверка комнаты с двумя учениками, независимости состояний, приватности, переподключения и порядка обновлений.

До двух звонков ученику сервер передаёт только его состояние. Учитель всегда получает состояния обоих учеников. Нажатие 🔔 проигрывает короткий звук и сразу блокирует собственные кубики. Сервер атомарно сохраняет последнюю комбинацию и фиксирует звонок; только после звонков обоих учеников передаёт им обе комбинации для сравнения. Правильность не проверяется.

Кнопка **NEW ROUND** есть только у учителя; сервер также проверяет его полномочия. Она снимает блокировки, убирает комбинацию партнёра и сбрасывает звонки без смены комнаты и участников. Текущие слова сохраняются. Номера раундов предотвращают применение задержанных запросов прошлого раунда.

Обновления имеют возрастающие номера: задержанный запрос не откатывает более новое положение. При потере сети локальные повороты и звонок повторно отправляются из открытой страницы; SSE переподключается автоматически. Не обновляйте страницу до синхронизации, если сеть отключена. Звук синтезируется средствами браузера при нажатии колокольчика, внешние звуковые файлы не нужны.

Комнаты хранятся в памяти. Перезапуск сервера удаляет их; комнаты без активности удаляются через 12 часов. Выход со страницы не освобождает место ученика: оно сохраняется для возврата/обновления страницы. Для другого состава участников создайте новую комнату. Имена можно повторять: ученики различаются по внутреннему идентификатору.

## Публикация

Нужен хостинг с постоянно работающим Node.js-процессом и поддержкой длительных HTTP-соединений (SSE). Команда запуска `npm start`, порт берётся из переменной `PORT` (по умолчанию 3000). Запускайте **один экземпляр** приложения, поскольку комнаты находятся в памяти. Статический хостинг вроде GitHub Pages для этой архитектуры не подходит.

Используйте HTTPS. Если перед сервером стоит Nginx, отключите буферизацию для `/api/events` и задайте `proxy_read_timeout 60s` или выше. Сервер отправляет heartbeat каждые 15 секунд. Тарифы и ограничения выбранного хостинга проверьте перед публикацией; засыпающий сервер может прервать урок и удалить комнаты.

Проект не опубликован автоматически: для доступа из разных сетей нужен общий публичный адрес сервера. Секретный токен даёт доступ к сессии участника; не пересылайте адрес SSE и содержимое sessionStorage. Ссылка приглашения содержит только код комнаты.

## Render Web Service: подготовка и публикация

Проект подготовлен для нативного Node.js Web Service. Публикация ещё не выполнена. Настройки задаются в Render Dashboard; файл `render.yaml` не требуется. Имеющийся Dockerfile можно оставить, но для описанного ниже способа явно выберите **Node**, если Render предложит Docker.

### Настройки

| Поле Render | Значение |
| --- | --- |
| Service type | Web Service |
| Language / Runtime | Node |
| Branch | Ветка с этой версией проекта |
| Root Directory | Пусто, если `package.json` находится в корне репозитория |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/` |
| Instances | 1; без автоматического масштабирования |

Обязательных пользовательских переменных окружения нет. Render задаёт `PORT` сам; не устанавливайте его вручную. Node 24.x выбирается по `engines.node` в `package.json`; отдельный `NODE_VERSION` не нужен. `NODE_ENV=production` можно задать явно, но приложение не требует этой переменной. Ключи API, DATABASE_URL и адрес отдельного backend не нужны.

### Шаги

1. Создайте репозиторий на GitHub и загрузите проект: `package.json`, `package-lock.json`, `server.js`, каталог `public`, тесты, README и `.gitignore`. Сохраните структуру: `public` — каталог, а `package.json` — в корне. Не загружайте `node_modules`, `test-results` и журналы.
2. В Render Dashboard выберите **New → Web Service**, подключите GitHub и выберите этот репозиторий.
3. Введите имя сервиса, выберите регион и ветку. Установите параметры из таблицы выше. Для проекта внутри подпапки репозитория укажите эту подпапку в Root Directory.
4. Выберите Free для пробной публикации либо платный экземпляр для уроков без сна по неактивности. Оставьте ровно один экземпляр. Чтобы коммиты случайно не перезапускали сервер во время урока, отключите Auto-Deploy.
5. Только когда будете готовы опубликовать сайт, нажмите **Create Web Service**: это запускает сборку и публикацию. До этого шага сайт в интернете не появляется.
6. После успешной публикации откройте выданный адрес `https://<имя-сервиса>.onrender.com`. Не добавляйте к нему порт `3100`, `3000` или `10000`.
7. Создайте новую комнату как Teacher и отправьте двум ученикам ссылку приглашения. Каждый открывает её на своём устройстве и вводит имя. Локальные комнаты на сервер Render не переносятся.
8. Проверьте на трёх устройствах: учитель видит повороты сразу; первый звонок блокирует только своего ученика и не раскрывает партнёра; второй раскрывает обе комбинации; NEW ROUND разблокирует оба набора в той же комнате.

### SSE и комнаты в памяти

HTTP-запросы используют относительные пути `/api/...`, EventSource подключается к `/api/events` на том же публичном домене, а приглашения используют `location.origin`. Render обслуживает HTTPS снаружи и передаёт запросы Node.js по HTTP; отдельный HTTPS-сервер или настройка CORS здесь не нужны.

SSE уже отправляет `Content-Type: text/event-stream`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, сообщение переподключения и heartbeat каждые 15 секунд. Подключения автоматически восстанавливаются браузером. Не включайте дополнительное кэширование для `/api/*`. Реальную доставку через инфраструктуру Render нужно проверить после публикации по шагу 8.

Все комнаты остаются в памяти одного процесса. Сон сервиса, перезапуск и новая публикация удаляют их; после этого учитель создаёт новую комнату. Несколько экземпляров имеют разную память, поэтому масштабирование включать нельзя. Диск или база данных для текущей версии не требуются.

На бесплатном тарифе Render сервис засыпает после 15 минут без входящего трафика и может быть перезапущен платформой. Исходящие SSE heartbeat не следует считать гарантией от сна: это не входящие HTTP-запросы. Это ограничение хостинга, а не изменение игровых правил.

Официальная документация: [Web Services](https://render.com/docs/web-services), [Node.js deployment](https://render.com/docs/deploy-node-express-app), [Node version](https://render.com/docs/node-version), [Free instance limitations](https://render.com/docs/free).
